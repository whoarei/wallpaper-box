壁纸盒子 · 模块化技术方案

壁纸盒子将 HTML 动态场景作为独立内容模块，通过 Tauri 与 WebView2 显示在 Windows 桌面层。0.3.0 随包提供水族箱和松风镇，直接从本地文件播放；新增壁纸可放入用户目录，也可从官方 GitHub 内容库逐项下载。

0.3.0：只发布 NSIS 安装版。程序自动检查新版并在后台下载、验签，准备完成后由用户确认安装；壁纸内容仍按单张选择下载，两条更新链路独立。日常播放不依赖 Docker 或本机 HTTP 服务器。
01

目标与边界

运行环境为 Windows x64、Explorer 桌面与 WebView2 Runtime。NSIS 安装版使用当前用户安装；0.3.0 起不再发布便携版，也不提供便携版在线升级。内置壁纸和已下载壁纸均可离线播放。

桌面显示选择显示器，为每屏切换壁纸；托盘提供切换、暂停、查看桌面和退出操作
内置内容aquarium 水族箱与 pinewind-town 松风镇，内容版本均为 1.0.0，最低程序版本仍为 0.2.0
水族箱互动管理窗口和托盘提供“投喂鱼儿”；不依赖桌面点击或全局输入钩子
新增内容本地文件夹 / ZIP 导入，或手动放入用户 local/；官方内容逐项下载安装

内容边界HTML / CSS / JavaScript 与静态资源；带独立后端的应用仍需自行提供后端
程序升级启动及每日自动检查；发现新版后后台下载并验签，确认“重启并升级”后安装
02

运行架构与请求流程

本地播放链路

  1. Rust 宿主定位随包 wallpapers/ 及用户壁纸根目录。
  2. 原生目录发现合并内置快照、官方已安装版本和自定义模块，返回卡片与独立警告。
  3. 用户选择壁纸后，宿主创建或复用相应显示器的 WebView 窗口。
  4. WebView 请求 http://wallpaper.localhost/<模块 ID>/<相对路径>，由 Tauri 注册的自定义协议处理器直接读取本地文件。
  5. 原生桌面层将程序自有窗口放到桌面图标下方，并维护位置、尺寸、暂停与恢复。

wallpaper.localhost 是 WebView 自定义协议映射的内部来源，不是对外运行的网站，也不占用 8088 或其他 TCP 监听端口。浏览器直接输入该地址不能替代壁纸程序。

职责划分

文件 / 组件职责
host.rs / desktop.rs管理命令、每屏状态、托盘、显示器维护及 Windows 桌面层
catalog.rs原生扫描、元数据校验、来源合并、活动版本与回退
protocol.rs按窗口作用域读取本地资源、MIME、范围请求与路径隔离
online.rs / packages.rsGitHub 清单缓存、单项下载、校验、受限解压与自定义导入
app_updates.rs主仓库更新清单、每日调度、后台安装包下载、Ed25519 验签与确认安装
ui/嵌入程序的管理界面；通过受限 IPC 访问宿主能力
03

Tauri 动态壁纸与系统托盘

日常操作

  1. 运行 wallpaper-box.exe。首次启动默认在主显示器使用水族箱，后续读取已有每屏选择与暂停状态。
  2. 在管理界面选择显示器，再从“我的壁纸”中选择场景。每块屏幕使用独立壁纸窗口。
  3. 左键托盘图标打开管理窗口；右键选择显示器、切换壁纸、暂停当前或全部、关闭当前壁纸、查看桌面或退出。
  4. 关闭管理窗口会收起到托盘。使用“退出壁纸盒子”结束程序并恢复原桌面背景。

水族箱投喂（沿用 0.2.1 修复）

选择正在播放 aquarium 的显示器，使用管理窗口或托盘右键菜单的“投喂鱼儿”。入口只在该屏幕使用水族箱时显示，手动暂停时禁用。遮挡自动暂停时允许先投喂，回到桌面恢复动画后鱼儿继续进食。加载中、页面自身暂停、食物未吃完或暂未响应时，程序显示对应提示。

宿主通过 aquarium-feed.js 调用现有 #feed.click()，沿用食物上限、鱼群吸引和涟漪逻辑；eval_with_callback 检查 totalFed 增加后才确认成功。修复在宿主层实现，不修改旧壁纸包，两张内置内容仍为 1.0.0，元数据 minAppVersion 仍为 0.2.0，无需为投喂更新内容仓库。

壁纸窗口保持鼠标穿透，原页面 HUD 隐藏。点击水面、原页面投喂按钮和 E 键用于浏览器独立模式；原生桌面投喂由管理窗口或托盘触发。程序不安装鼠标 / 键盘全局钩子，不注册投喂全局快捷键。

桌面层与资源节约

经典桌面通过 WorkerW 子窗口承载壁纸；部分较新 Windows 11 使用 Progman 下的透明合成子窗口。宿主只操作自己的 HWND，不移动 Explorer 图标窗口。窗口以物理像素定位，维护循环检测显示器连接、位置和桌面层变化。

壁纸窗口鼠标穿透，原页面说明控件在壁纸模式下隐藏。宿主对 requestAnimationFrame 动画提供暂停包装；单个普通窗口覆盖屏幕达到阈值时可自动暂停，恢复可见后继续。手动暂停优先，多个小窗口合计遮挡不作为当前检测依据。实际 CPU / GPU 占用随分辨率、场景和显示器数量变化。

├─ settings.json              每屏选择、选中屏幕与暂停设置
├─ diagnostics.json           当前显示器与窗口状态

04

程序在线升级与确认安装

程序更新来自 whoarei/wallpaper-box，固定清单入口为 releases/latest/download/latest.json。这是主程序升级入口；壁纸内容继续使用另一仓库的 catalog.json 和独立 ZIP。

检查、下载与安装时机

  1. 每次启动先恢复缓存并重新验签，再延迟 5 秒检查一次。持续运行时每 60 秒观察本地日期，在新日期再检查一次；失败也计入当天已检查，不在当天后台循环重试。同日重新启动仍会执行启动检查。
  2. 发现高于当前版本的正式版本后，立即后台下载该版本 NSIS 安装包并校验签名及版本绑定。壁纸窗口继续播放。
  3. 下载、校验完成进入 ready，管理界面只提示可升级，不退出、不安装。
  4. 用户点击“重启并升级”，再次确认后才启动安装并退出当前程序；取消确认则保留当前运行状态。安装请求必须携带用户确认的目标版本，候选版本变化后须重新确认。
  5. 安装升级保留已下载壁纸、自定义内容、每屏壁纸选择及暂停设置；内置快照随程序资源更新。
情形处理
自动检查失败显示失败状态；当天不反复后台重试，可手动检查、下次启动或下一天再试
下载或验签失败不安装未验证文件，当前程序及本地壁纸继续运行
已准备好但未确认保留可升级提示，用户决定安装时机
0.2.x 升到本版旧版没有程序升级器，先从 Release 手动安装一次 0.3.0；后续版本可走在线升级
便携版后续仅发布安装版，不提供便携版升级链路

接口 / 字段约定

├─ pending.json                          候选版本的服务器原始清单

更新信任与版本绑定

安装包使用 Tauri 的 Base64 包装 minisign 格式 Ed25519 更新签名，程序内置公钥。清单版本、固定官方 Release 地址、安装包文件名和可信签名注释中的版本必须一致；签名命令通过 --app-version 绑定版本，运行时启用 requireSignedVersion。未知来源、旧版本或不匹配的签名不得进入可安装状态。清单上限 1 MiB，安装包上限 128 MiB，网络请求只接受 HTTPS 和允许的官方跳转目标；下载与校验失败不修改当前安装。

私钥仅保存在工作区之外，本地通过 TAURI_SIGNING_PRIVATE_KEY_PATH 指向文件，GitHub Actions 使用 TAURI_SIGNING_PRIVATE_KEY Secret；当前密钥密码为空，TAURI_SIGNING_PRIVATE_KEY_PASSWORD 使用空值。私钥不得提交到仓库、写入日志或放入安装包。程序只携带更新公钥。minisign 更新签名验证程序认可的升级来源；Windows Authenticode 属于另一套代码签名，当前尚未配置，不能把更新已签名表述为 Windows 安装包已获认证。

程序更新与壁纸内容更新分别维护仓库、清单、版本和安装逻辑。自动下载只针对新版程序安装包；壁纸仍需用户逐张选择下载，不会自动拉取整个内容库。

Set-Location wallpaper-host

npm run check:version
npm run bundle
./scripts/package-release.ps1 -RequireSigned
./scripts/verify-release.ps1 -Directory ../release/v0.3.0 -RequireSigned

构建环境另需提供更新签名密钥。package-release.ps1 生成上述五项发布产物；verify-release.ps1 核对版本、官方地址、外层大小和 SHA-256、更新签名与清单。verify-installer.mjs 通过 7-Zip 读取 NSIS 载荷，与 schema 3 的 installerFiles 逐项核对；不再依赖便携 ZIP。校验禁止 portable.flag、用户壁纸、设置、缓存、私钥与编译产物入包。默认 7-Zip 路径为 C:\Program Files\7-Zip\7z.exe，可作为脚本第二个参数覆盖。

模块接入规范

最小自定义模块

local/
  my-scene/
    index.html

直接将文件夹放入用户 local/，或使用“导入文件夹 / 导入 ZIP”。不提供元数据时，默认入口为 index.html、名称为文件夹名、版本为 1.0.0。所有图片、脚本和样式应使用相对路径，保证离线播放。

完整 module.json

{
  "schemaVersion": 1,
  "id": "my-scene",
  "type": "web",
  "name": "我的风景",
  "subtitle": "MY SCENE",
  "description": "一张可离线播放的动态场景。",
  "version": "1.0.0",
  "minAppVersion": "0.2.0",
  "entry": "index.html",
  "cover": "cover.jpg",
  "tags": [
    "风景",
    "动画"
  ],
  "order": 30,
  "enabled": true
}
字段规则
schemaVersion / type当前为 1 / web
id / 文件夹名小写字母、数字、连字符，1～64 字符，首字符为字母或数字；拒绝 Windows 设备保留名
name / subtitle / description名称与副标题最多各 80 字符，描述最多 300 字符
version / minAppVersion语义化版本；当前程序必须满足最低版本要求
entry目录内存在的相对 HTML 路径，默认 index.html
cover可选相对封面路径；未指定时寻找约定的 cover 文件；无封面仍可显示卡片
tags / order / enabled最多 8 个标签、每个 30 字符；order 为整数，默认 100；enabled 默认 true
module.jsonUTF-8 JSON 对象，不超过 64 KiB；不支持注释或末尾逗号

自定义内容统一使用 local:<folder-slug> 作为运行 ID；即使 module.json 写了与官方相同的 id，也不会覆盖内置或官方模块。官方 ZIP 的 id、版本、最低程序版本与入口必须和清单一致。

路径必须位于当前模块内；禁止绝对路径、反斜杠、冒号、百分号二次解码、点段、设备名等不安全形式。坏模块被单独跳过并给出警告，其他壁纸仍可使用。
08

原生目录发现与优先级

  1. 扫描随包 wallpapers/，建立内置壁纸基线。
  2. 读取用户 online/<id>/active.json；活动版本有效时，以同 ID 的已下载版本覆盖内置快照。
  3. 扫描用户 local/，以 local:<slug> 独立加入自定义壁纸。
  4. 逐模块验证元数据、版本兼容性、入口及目录边界，按 order 和 ID 排序。
  5. 管理界面显示合并后的“我的壁纸”与警告；维护扫描或“刷新”按钮重新发现目录变化。

内置、官方、自定义三种来源共用同一显示链路。官方活动指针可回到 builtin，此时同 ID 使用随程序提供的快照。自定义 ID 与官方 ID 隔离。新增或更新内容不改变 Tauri 资源映射，也不需要重新安装程序。

自动发现更新目录列表，不承诺对运行中的任意网页源文件热替换。修改正在播放的 HTML / JS 后，可重新应用该壁纸；复制大模块时建议先在 local 之外完成，再一次移入，避免被扫描到半成品。

09

GitHub 在线壁纸库与安全安装

官方仓库为 whoarei/wallpapers，稳定清单入口为 releases/latest/download/catalog.json。客户端匿名读取公开 Release，无需 GitHub 登录或个人令牌。

用户操作与下载边界

  1. 打开“在线壁纸”，点击“检查更新”。程序只请求清单并显示封面、可安装版本和更新状态。
  2. 用户选择某一张壁纸的“下载 / 更新”，程序才下载该条目的一个版本 ZIP；不会自动安装全库。
  3. 校验 ZIP 大小和 SHA-256，在用户暂存目录内受限解压；再核对元数据、入口和兼容性。
  4. 将完整版本写入 online/<id>/<version>/，原子替换 active.json 的活动指针。
  5. 保留上一活动版本，提供回退；安装和播放不要求持续联网。
{
  "current": "1.1.0",
  "previous": "1.0.0"
}

previous 也可以是 builtin，用于回到内置快照。回退交换 current 与 previous；更新失败不得把不完整目录设为活动版本。下载与导入路径检查拒绝链接、越界、大小写重名、设备名和非法 ZIP 路径，并限制文件数量及解压大小。

断网时可继续播放现有壁纸；最近可用清单缓存在原 AppData 设置目录的 online-catalog.json。SHA-256 用于比对发布清单和下载文件的一致性，内容仍由官方仓库维护；程序将管理能力限制在管理窗口，自定义壁纸窗口没有下载或文件管理权限。

官方库独立发布

维护流程见 壁纸仓库 README：新增 wallpapers/<id>/ 和完整元数据，修改内容时提升该壁纸版本，独立提升 library.json 的清单版本，运行 python scripts/build.py，检查后提交并推送 library-vX.Y.Z 标签。内容 CI 生成每张 ZIP、封面、catalog.json 和校验文件，公开 Release 后稳定入口指向新清单。

主程序 0.3.0 内置仍为原来的两张壁纸。“通往别处的窗户”由内容仓库独立提供，用户检查后单项下载和离线应用；它不需要加入 EXE 或重新发布主程序。程序升级器的自动下载策略不适用于壁纸库。

本地协议与权限边界

接口 / 位置行为
管理窗口 IPC仅 manager 窗口可调用；Tauri 命令 ACL 与宿主窗口标签检查同时限制
feed_aquarium管理窗口或原生托盘操作当前显示器；校验 aquarium 分配与手动暂停，并确认页面回执
http://wallpaper.localhost/<id>/<relative>Tauri 内部协议映射；读取已发现模块中的静态资源
资源请求方法GET / HEAD；支持单个字节范围请求；不提供写入接口
管理窗口资源作用域允许读取模块封面等已发现资源
每屏壁纸资源作用域仅允许读取该窗口被分配的壁纸 ID，跨模块请求被拒绝
路径与响应一次百分号解码、规范化目录边界检查、MIME、no-store、CSP 与 nosniff
程序升级管理仅管理窗口可检查和确认安装；壁纸页面不具备升级能力
旧 /api/modules仅属于 Legacy 浏览器示例，桌面主程序不再调用

管理窗口可以选择目录、导入、更新与切换壁纸；壁纸页面只负责显示自身内容。协议处理器对实际文件做规范化边界检查，拒绝跨壁纸目录读取；未知窗口标签不给予默认全库权限。完整单文件响应上限为 64 MiB，单次范围响应上限为 8 MiB，避免无界读取。

这些能力隔离避免壁纸脚本调用主程序管理命令。自定义壁纸本身仍是用户导入的网页内容，应按其来源选择；本协议不提供任意系统文件访问或模块后端进程启动。

安装、离线使用与日常维护

  1. 从 主程序 Releases 下载 Windows x64 NSIS 安装包。
  2. 安装后运行 EXE。0.2.x 用户需先手动安装一次 0.3.0，才能使用后续程序在线升级。
  3. 首次在主屏查看水族箱，然后按需选择显示器和壁纸。已有 WebView2 时，两张内置壁纸无需网络。
  4. 新增自定义内容时点击“打开壁纸目录”，将完整模块放入 local；也可使用导入按钮。
  5. 需要新官方内容时进入“在线壁纸”，检查后逐张下载；回到“我的壁纸”应用。

从 Docker 版迁移与状态兼容

旧展示服务位于 display-service/，作为 Legacy 浏览器开发示例保留。本地优先版本使用根目录 wallpapers/aquarium 和 wallpapers/pinewind-town 两张快照打包，不再从 8088 获取模块或启动 Compose。

既有自定义网页可从旧 display-service/modules/<slug> 复制到用户 local/<slug>，或通过“导入文件夹”接入；检查相对资源路径和元数据后刷新。旧目录里的其他模块不会未经选择自动导入。

应用标识不变，原显示器选择、壁纸 ID 与手动暂停设置继续沿用；原两张壁纸 ID 保持 aquarium / pinewind-town。自定义内容使用 local: 前缀，需要在管理界面选择对应模块。0.2.x 没有程序在线升级能力，安装一次 0.3.0 后才启用后续签名更新流程；便携版迁移和便携升级不在本次范围内。

网页 localStorage 按来源隔离。旧 http://127.0.0.1:8088 与新的 wallpaper.localhost 来源不同，种花记录、页面内设置等不保证自动迁移；需要时应为具体壁纸单独增加导出 / 导入。保留宿主 settings.json 不代表网页存储全部兼容。

后续扩展

普通网页壁纸通过 module.json 与内容目录扩展，不要求特殊 SDK。新增宿主能力、权限或新的模块类型需要主程序升级；纯内容和既有 web 模块的更新通过内容库独立发布。若要把本地目录分享为浏览器网站，可继续参考 Legacy Compose 示例，但它与桌面运行链路独立。
