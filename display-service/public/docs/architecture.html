本机 Docker 展示服务 / Tauri Windows 壁纸宿主

壁纸盒子 · 模块化技术方案

将动态桌面、全屏风景和静态小工具收敛到统一入口。新增模块只需放入一个文件夹，首页自动发现；松风镇作为第一个模块保留原访问地址。

日常新增模块：放入 modules/<模块名>/index.html，直接访问 http://127.0.0.1:8088/<模块名>/。可选的 module.json 定义名称、封面、入口和排序。
01

目标与边界

本次改造保留一个固定的本机端口，将模块内容与运行服务分开。纯前端模块的添加、页面编辑、元数据修改和列表移除，都不需要修改 Compose、重新构建镜像或重启容器。

事项运行方式
展示入口http://127.0.0.1:8088/
松风镇/pinewind-town/，迁移前后保持一致
访问范围只绑定本机回环地址；Docker Desktop 需要处于运行状态
适用模块HTML / CSS / JavaScript 与静态图片、音视频资源
带后端的应用仍需独立启动后端并按需添加反向代理；放文件夹不会自动启动服务端程序
02

运行架构与请求流程

两个轻量服务

  • web：官方 Nginx 稳定版镜像，负责网页与资源访问、目录接口代理和可选应用代理。
  • registry：Node.js 24 Alpine 镜像，仅使用标准库。读取目录和 JSON，返回模块列表，不安装依赖、不执行模块代码。

两个服务都将同一宿主机 modules/ 目录只读挂载到 /srv/modules。目录服务不向宿主机发布端口，浏览器统一经 Nginx 的 8088 端口访问。

Nginx 使用 Docker 内置 DNS 动态解析 registry，避免目录容器重建后沿用旧 IP。自动发现不依赖文件监听事件，每次调用接口都重新扫描。

03

Tauri 动态壁纸与系统托盘

壁纸盒子 0.1.0 是独立的 Windows Tauri 2 程序。管理界面嵌入可执行文件，壁纸由 WebView2 直接加载原有 Docker 模块地址；松风镇和水族箱继续共用同一套源码。新增模块后，网页首页与壁纸程序都从 /api/modules 发现，无需重新编译宿主。

部分职责
Rust / Tauri枚举显示器、持久化每屏选择、创建 WebView、托盘菜单、遮挡检测
Windows 原生桌面层将自有 HWND 挂入 Explorer 的 Progman / WorkerW，保持在桌面图标下方
WebView2加载 /pinewind-town/、/aquarium/ 等现有模块
模块目录仍位于 display-service/modules/；不复制进 EXE

启动与日常操作

# 先确认本机展示服务运行
Set-Location -LiteralPath 'E:\codex-proj\desktop\display-service'
docker compose up -d --wait

# 运行便携程序
& 'E:\codex-proj\desktop\wallpaper-host\artifacts\wallpaper-box.exe'
  • 首次启动将水族箱应用到主显示器；后续启动恢复上次每屏选择与暂停状态。
  • 管理界面先选显示器，再点壁纸卡片。每块屏幕使用独立壁纸窗口；切换时复用该窗口。
  • 左键托盘图标打开管理窗口；右键选择显示器、切换壁纸、暂停当前或全部、关闭当前壁纸、显示桌面或退出。
  • 关闭管理窗口会收起到托盘。选择“退出壁纸盒子”才结束程序并恢复原桌面背景。
  • “查看桌面”调用 Windows Shell 的 ToggleDesktop，并在 3 秒后保存当前屏幕 PNG，便于确认实际图标与壁纸层级。

窗口、显示器与节能

经典桌面使用 WorkerW 子窗口；本机较新 Windows 11 使用 Progman 下的透明合成子窗口。仅修改程序自己的窗口，不迁移 Explorer 图标窗口。窗口按原生物理像素设置位置和尺寸，支持负坐标与不同 DPI。每 2 秒重新检查连接、窗口层级与大小；屏幕断开后保留配置，重新连接时恢复。

壁纸模式隐藏原模块的说明面板，并让鼠标穿透，桌面图标保持可操作。宿主注入可暂停的 requestAnimationFrame 包装器；单个普通窗口覆盖屏幕至少 95% 时自动暂停。显示桌面或移开窗口后恢复，手动暂停优先。多个小窗口合计遮挡暂不计算。

Windows 安装包与 GitHub CI 发布

首版版本号为 0.1.0，对应标签 v0.1.0，发布目标为 whoarei/wallpaper-box。Windows x64 安装程序采用 Tauri NSIS 当前用户安装模式；便携版完整解压后运行。安装版和便携版均带有展示服务配置、松风镇、水族箱及本 HTML 文档。

安装后首次使用

  1. 安装并启动 Docker Desktop，选择 Linux 容器。
  2. 运行壁纸盒子；缺少 WebView2 时安装版会下载 Microsoft 官方运行时。
  3. 内容服务未连接时，点击“启动内容服务”。程序在后台执行随包 Compose 配置，首次需要下载固定镜像。
  4. 选择显示器与壁纸。已有健康的 8088 目录服务会直接复用，避免替换用户的模块目录。

新增模块放入正在提供内容的 display-service/modules/。安装版资源位于安装目录，便携版位于解压目录；设置与 WebView 数据继续保存在 AppData，发布包不包含本机设置、桌面截图或日志。

自动化构建与发布触发

.github/workflows/windows.yml 在 main 推送、PR 和手动运行时构建并上传 Actions Artifact；只有推送版本标签时才运行有写权限的发布任务。构建任务只读仓库，发布任务使用 GitHub 自动提供的 GITHUB_TOKEN，不需要额外配置个人令牌。

  1. 固定 Action 提交、Node.js、Rust 与 CLI 版本，恢复缓存。
  2. 校验 Cargo / Tauri / npm 版本与标签一致，执行模块目录测试、JavaScript 语法和 Rust 格式检查。
  3. 构建 NSIS 安装程序并执行 Rust 测试。

  5. 标签发布创建草稿，上传四个产物后回下载，重新校验每个产物的哈希。
  6. 全部成功才公开 Release；失败保留草稿，已发布版本重跑不会覆盖文件。

模块接入规范

最小模块

modules/
  aquarium/
    index.html

无需元数据也可发现：名称默认为文件夹名，入口为 index.html，排序值为 100；缺少封面时，首页使用默认视觉封面。模块中的资源应使用相对路径，例如 ./assets/fish.png。

完整元数据示例

{
  "name": "水族箱",
  "subtitle": "AQUARIUM",
  "description": "一小片安静游动的海。",
  "entry": "index.html",
  "cover": "cover.webp",
  "tags": [
    "海底",
    "慢生活"
  ],
  "order": 20,
  "enabled": true
}
字段规则与默认值
文件夹名1～64 个小写字母、数字或连字符，首字符为字母或数字；保留名：api、assets、docs、healthz
name / subtitle可选字符串，最多 80 字符；name 默认为文件夹名
description可选说明，最多 300 字符
entry相对 HTML 路径，默认 index.html，最多 256 字符；支持 view/start.html；首页链接指向该文件
cover相对图片路径，最多 256 字符；支持 webp、jpg、jpeg、png、svg、avif、gif
自动封面不指定 cover 时，依次寻找 cover.webp、cover.jpg、cover.png、cover.svg
tags最多 8 个字符串，每个最多 30 字符
order有限数值，默认 100；越小越靠前，同值按文件夹名排序
enabled布尔值，默认 true；false 仅从首页隐藏，不阻止通过原 URL 访问
module.jsonUTF-8 JSON 对象，不超过 64 KiB；不支持注释或末尾逗号
入口和封面必须位于当前模块目录内。入口不存在、元数据损坏或字段类型不合法时，只跳过该模块；错误原因出现在 API 的 warnings 中，其他模块继续显示。封面缺失则回退到默认封面。
07

自动发现与页面更新

  1. 首页首次打开时请求 GET /api/modules。
  2. 目录服务列出 modules/ 的直接子目录，排除保留名称、无效名称和目录符号链接。
  3. 读取可选元数据，校验入口与封面文件，生成 URL 并排序。
  4. 首页根据结果生成卡片，渲染元数据时使用文本节点，避免将字段当作 HTML 执行。
  5. 页面可见时每 5 秒重新请求；重新聚焦或切回页面时立即更新。页面隐藏时暂停请求。

API 和静态内容均设置 Cache-Control: no-store。列表内容没有变化时不重建卡片。模块页面正在播放时，修改其源文件仍需刷新该模块页面；目录自动更新不会强制中断正在展示的内容。

添加、修改与移除

  • 添加文件夹：API 下一次请求即可发现，打开的首页通常在下一个 5 秒轮询周期显示。
  • 修改名称、封面路径、排序或 enabled：首页自动更新；同一路径的图片内容替换可刷新首页重新载入。
  • 删除或移出文件夹：首页下一次更新时移除卡片；之前的页面地址随后返回 404。
  • 复制大型模块：建议先以点开头的暂存目录复制，完成后重命名为合法模块名，避免未复制完成就被列出。

HTTP 接口与路由

路径行为
/首页，从目录接口生成卡片
/<模块名>/通用目录路由，默认返回 index.html
/<模块名>/<相对文件>模块内静态资源或自定义 HTML 入口

/docs 或 /docs/重定向到本技术方案

目录响应示例

部署与日常维护

在服务根目录执行以下命令。镜像以摘要固定，首次部署需能获取对应镜像，正常运行不需要 npm 安装或构建步骤。

Set-Location -LiteralPath 'E:\codex-proj\desktop\display-service'
docker compose up -d --wait
docker compose ps
docker compose logs --tail 50 web registry

# 停止服务；手动停止后不会自动恢复
docker compose stop

# 再次启动
docker compose up -d --wait
改动需要的操作
新增 / 修改 / 移除静态模块修改 modules/ 内容；无需重启
修改 module.json保存即可，等待首页下一次更新
修改首页 HTML / CSS / JavaScript刷新首页
修改 registry/server.cjsdocker compose restart registry；无需镜像重建
修改 Nginx 路由先 nginx -t，成功后 nginx -s reload
修改 Compose、镜像、挂载或环境变量docker compose up -d --wait 应用配置
docker compose exec web nginx -t
# 只有检查成功后才执行
docker compose exec web nginx -s reload

容器使用 restart: unless-stopped；Docker 引擎启动后会恢复未被手动停止的服务。此配置不修改 Docker Desktop 自身的开机启动设置。

web 的健康检查同时验证自身和目录接口；registry 单独验证内部健康端点。目录容器不发布宿主机端口，web 仅发布 127.0.0.1:8088。

10

松风镇迁移与状态兼容

松风镇统一迁入 display-service/modules/pinewind-town/，取消针对单个场景的文件挂载和专用 Nginx 路由。首页不再写死模块卡片，名称与说明来自该模块的元数据。

迁移保留 HTML 原始字节和 http://127.0.0.1:8088/pinewind-town/ 地址。浏览器的 localStorage 属于同一来源，所以该来源下的种花记录可以继续使用。此前 47831 端口的临时预览属于另一个来源，其记录不会自动迁入 8088。

模块源码无需为自动发现增加特殊 SDK、生命周期接口或构建脚本。已有的静态页面可以直接按目录接入。

验收与回归检查

本次验证覆盖目录逻辑与实际运行的 Docker 服务，重点检查新增模块时服务持续运行。

  • 五组 Node 标准测试：新增、重命名、入口变化、元数据与排序、坏模块隔离、路径校验和 HTTP 行为。
  • 运行环境检查：临时加入模块、修改元数据、损坏 JSON、隐藏模块和移除模块；整个过程中容器 ID 与启动时间保持一致。
  • 路由检查：首页、CSS / JS、健康端点、松风镇原地址及原始 HTML 哈希，缺失页面与非公开文件返回 404，非法 API 方法返回 405。
  • 浏览器检查：首页在不手动刷新的情况下自动出现和移除新卡片，桌面和手机布局不产生横向溢出。
node --test tests/registry.test.cjs
node tests/verify-running.cjs

浏览器测试脚本为 tests/gallery.browser.cjs，需要现有 Playwright 模块和浏览器路径。HTML 文档还按 RTD 文档技能检查目录、10 套配色、主题恢复、无脚本阅读、窄屏和打印样式。

首页只显示默认封面检查 cover 相对路径与图片格式；未指定时可使用约定的 cover 文件名
后台目录正常但首页未更新重新聚焦首页；检查浏览器网络请求；需要时刷新首页脚本
模块页面正常、API 不可用docker compose ps；查看 registry 日志；目录服务恢复后首页会继续更新
Docker 未运行时页面打不开启动 Docker Desktop，再检查服务状态；曾手动停止时执行 up -d --wait

应用代理扩展

routes/local-app.conf.example 是默认不启用的代理示例。复制为 .conf 后设置路径和上游，再执行配置检查与热加载。Windows 宿主机应用可使用 host.docker.internal，但应用需能从 Docker 网络访问，并正确配置 base URL。静态模块目录不会承担进程管理或后端依赖安装。
